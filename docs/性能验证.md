# 第一版核心性能验证

日期：2026-09-22。环境：macOS 27.0，Apple Silicon（arm64），Rust release 优化构建。

## 结论

当前纯 Rust 后台核心的内存占用较低：待机约 1.91 MiB，接收测试中的采样峰值约 2.36 MiB。64 MiB 与 512 MiB 文件传输时内存没有随文件大小成比例增长。

满速本机回环传输会使用接近一个 CPU 核心。此原型尚未加入限速功能，不能据此承诺“传输时几乎不占 CPU”。

| 项目 | 测量结果 |
| --- | --- |
| 可执行文件体积 | 0.48 MiB |
| 待机接收进程 RSS | 1.91 MiB |
| 待机采样时长 | 15.16 秒 |
| 待机 CPU | 采样精度内未观察到累计 CPU 时间增长 |
| 64 MiB 文件 | 0.274 秒，233.2 MiB/s |
| 512 MiB 文件 | 1.822 秒，280.9 MiB/s |
| 两次传输接收端采样峰值 RSS | 均为 2.36 MiB |
| 512 MiB 传输接收端平均 CPU | 98.2%，约一个逻辑核心 |

原始记录见 [benchmark-macos.json](benchmark-macos.json)。

## 测量方法与边界

- 发送端、接收端在同一台 Mac，使用 127.0.0.1 TCP 回环地址。
- 文件进行逐块加密，并在接收完成时同步磁盘；测试端随后独立比较 SHA-256。
- RSS 由系统 ps 采样，传输时约每 25 毫秒采样一次；CPU 由累计 CPU 时间差除以经过时间得到。
- 采样可能遗漏短时峰值，15 秒待机也不足以判断长时间唤醒、耗电或睡眠恢复表现。
- 表中内存与 CPU 仅属于接收进程，不含发送进程、测试脚本或未来界面。
- 吞吐量受到本机缓存影响，不能代表两台电脑之间的 Wi-Fi、网线或长期磁盘写入性能。
- MiB 为 1024 × 1024 字节。

## 已通过的验证

- 中文文件名、零字节文件及文件完整性。
- 重名文件自动加前缀，不覆盖已有文件。
- 错误密钥拒绝接收。
- 连接中断后服务仍可接收后续任务。
- 传输中断、密文损坏后清理临时文件，不产生正式文件。
- 路径穿越和常见 Windows 非法文件名检查。
- 本机单播发现；另外独立验证了按网卡子网广播发现，在当前两张有 IPv4 地址的网卡上均发现本机服务。
- Rust 单元测试及 Clippy 静态检查。
- Windows x86_64 MSVC 目标 cargo check 通过；此项不等于已完成 Windows 链接、生成 exe 或实机运行。

## 待验证

1. Mac 与 Windows 双向传输、实际网络吞吐和两端资源占用。
2. Windows 防火墙及 macOS 本地网络权限首次使用体验。
3. 1 GiB 以上文件、长时间待机、睡眠恢复及网络切换。
4. 菜单栏／托盘界面加入后的整机进程总占用。
5. 正式配对与标准协议选型；当前实验协议不兼容 LocalSend。
