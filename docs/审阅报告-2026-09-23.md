# 邻传 0.2.0 界面重做与代码审阅

日期：2026-09-23。范围：`src/` 全部代码、测试、构建与生成脚本、文档。另有一轮独立审阅（只读代码并对照依赖库源码核实），结论已合并到下文。

## 界面重做

- 新的视觉系统：统一配色、圆角卡片、细阴影、自绘矢量图标；浅色 / 深色外观跟随系统，两套样式都已完整定义。
- 顶部：应用标志、接收状态标签（可接收 / 已暂停 / 不可用，悬停显示原因）、“⋯”菜单（收起、打开接收文件夹、退出）；分段标签页，进行中的任务数显示在“传输记录”上。
- 传文件：设备卡片（选中高亮）、搜索中与无设备状态、手动 IP；虚线拖放区（拖入文件时整窗提示）；已选文件列表按类型显示图标、大小，可逐个移除；发送按钮固定在底部，写明文件数和接收设备。
- 传输记录：进行中的任务排在最前，显示方向、对方设备、进度条、百分比与速度；完成、失败、取消分别着色。
- 设置：分组卡片、开关代替复选框、IP 一键复制、密钥显示 / 隐藏；未保存更改时提示并可“还原”。
- 对话框：收到文件时显示发送方、文件类型与大小、剩余等待秒数和排队数量；退出确认会先结束任务再关闭窗口。
- 自绘控件支持键盘焦点框；提示条替代原先插在页面顶部的通知。
- 应用图标：保留原有“双向箭头”设计，改为抗锯齿与渐变；Mac 图标采用系统图标网格并带投影；Mac 菜单栏改用随菜单栏明暗变化的单色模板图标。

## 已修复的问题

按影响从大到小排列。“推断”表示依据代码与依赖库行为得出，尚未在对应系统实机复现。

1. **界面文字全部以最细字重显示。** `NotoSansSC.ttf` 是可变字体，默认字重为 100（Thin），egui 无法选择字重；英文还落到 Ubuntu Light。改为由 `scripts/make_fonts.py` 生成静态 Regular（完整字符）与 SemiBold（常用字子集，用于标题），程序体积减少约 5 MB（Mac 通用版两个架构各含一份字体，约减少 10 MB）。
2. **Windows：收起到托盘后可能无法再唤起（推断）。** Windows 不向隐藏窗口发送绘制消息，eframe 因此不再运行界面逻辑：托盘“打开邻传”、再次启动、收到文件时的确认框、托盘“退出”都会失效，收到的请求 110 秒后被自动拒绝。现在直接调用 Win32 `ShowWindowAsync` 显示窗口。
3. **UDP 发现端口被占用时，接收服务整体停止。** 原逻辑在 UDP 绑定失败后直接返回，已绑定的 TCP 监听随之关闭。现在只提示“无法被自动发现”，仍可按 IP 接收。
4. **Windows：发现服务可能永久停止（推断）。** Windows 会把此前回复引起的 ICMP 错误报告为 `ConnectionReset`，原来的接收循环遇到任何错误即退出。现在忽略这类瞬时错误。
5. **拒绝只对当前文件生效。** 发送方会继续逐个请求同一批剩余文件（100 个文件需拒绝 100 次，无人应答时确认框反复弹出）。现在拒绝或超时后停止本批，其余标记为“未发送”。
6. **发送方取消后，接收方确认框仍停留到超时，点接受才报错。** 接收方现在在等待期间检测连接是否已关闭，并自动撤回请求。
7. **接收方取消停滞的传输需等 15 秒读取超时；“结束任务并退出”会留下临时文件。** 接收端也加入取消监视，取消立即生效；退出前最多等待 2 秒，让任务删除临时文件。
8. **系统切换深色模式后界面样式错乱。** 原先只修改了启动时所用外观的样式，切换后变成 egui 默认深色样式、默认字号。
9. **大文件落盘超过 15 秒时，发送方误报超时（文件实际已保存）。** 最终确认的等待时间放宽到 5 分钟。
10. **错误信息混有英文**，如 “Wrong key or damaged/out-of-order frame”“failed to fill whole buffer”。现已全部转为中文；握手阶段被断开时会提示检查两边密钥和对方是否允许接收。
11. 连接密钥校验会接受 `+` 号（`u8::from_str_radix` 的特性），现改为严格十六进制。
12. 文件名中的双向控制字符（如 U+202E）可伪装真实扩展名，现一律拒绝。
13. 设置页原先每帧枚举网卡，现改为 5 秒缓存。
14. 接收服务的启动错误会被随后的设备发现结果覆盖，现单独保存，并显示在状态标签上。
15. 单实例端口被其他程序占用时程序静默退出，现在弹出说明。
16. 拒绝、确认超时和取消原先显示为红色“未完成”，现改为中性状态，并且不再覆盖状态栏；已发送记录显示对方设备名；等待确认的对话框显示剩余时间。

自动测试从 16 项增至 22 项：新增 4 项网络测试并扩充原有用例，覆盖第 5、6、7、10、11、12、16 条；界面测试改为在浅色和深色下渲染全部页面与对话框，另新增标题字体子集覆盖检查和地址显示检查。

## 未修改的建议

以下需要产品决策或实机验证，本次未改动：

- **未认证连接可占满接收名额。** 同一局域网中没有密钥的设备，可以开 4 个连接并缓慢发送握手数据，长期占住全部 4 个接收名额。建议给握手和请求设定总时限，并按 IP 限制连接数。
- **Cmd+Q 绕过退出确认。** winit 在 macOS 上默认创建带 Cmd+Q 的菜单，会直接退出、跳过退出确认。可通过 `event_loop_builder` 关闭默认菜单，但需要把 `winit` 加为直接依赖。
- **读屏软件无法读取界面。** 未启用 eframe 的 `accesskit` 功能，VoiceOver / 讲述人读不到界面内容。
- **收到的文件没有来源标记。** macOS 隔离属性和 Windows `Zone.Identifier` 都没有写入，收到的程序打开时不会触发 Gatekeeper / SmartScreen 提示。可在 Info.plist 加 `LSFileQuarantineEnabled`，或在 Windows 写入 `Zone.Identifier`。这也会让用户打开收到的文件时多一次提示。
- **每个文件都要单独确认。** 整批确认需要修改协议。
- **`tests/verify.py` 放错位置。** 它只适用于 0.1 原型，建议移到 `prototypes/`。
