# 邻传 0.3.0 功能与界面审阅

日期：2026-09-24。范围：`src/` 全部代码、测试、打包脚本与文档。方法：通读代码；在 Linux x86_64 容器（Rust 1.94）中编译 `--features demo`；运行 20 项自动测试；在虚拟显示器中以真实窗口渲染 11 个演示场景，截取浅色、深色、460×660、400×540 最小窗口和 900×800 加宽窗口共 24 张截图逐一检查。未在 Mac / Windows 实机运行，标注“推断”的条目需要实机核实。

## 总体评价

0.3 的方向是对的：免密钥配对、整批一次确认、文件夹与文字、设置即时生效，把 0.2 反馈的四个主要痛点都解决了。代码结构清晰（模型 / 线路 / 网络 / 发现 / 界面分层，界面再按页面拆分），接收端在写盘前的校验很扎实，取消、超时、临时文件清理等边角情况都有处理并有测试覆盖。界面在浅色与深色下一致，最小窗口下各页面与对话框都能放下。

自动测试 20 项全部通过；`cargo build --release --features demo` 无警告。

下面按影响从大到小列出问题。前三条建议在下一个版本处理。

## 功能与安全

1. **右键“信任此设备”信任的是未经验证的身份。** 设备网格中的设备来自 UDP 广播，广播里的 `id`、`name` 任何人都可以伪造。右键菜单“信任此设备”直接把广播声称的 ID 写入信任列表（`src/ui/home.rs` 调用 `network::trust`），没有经过握手，也不显示指纹。同一网络中的攻击者只要广播一个叫“办公室电脑”的设备，用户右键信任后，攻击者就能免确认向本机写文件。相比之下，收件确认框里的“信任此设备”是在握手证明身份之后才生效的，是安全的。建议：去掉右键菜单的信任入口，只保留“取消信任”；或者右键信任时弹出指纹核对框，并在首次握手后才真正写入。

2. **文字消息不需要确认，任何同网设备都能让本机弹窗。** `receive_text` 只要 `receive` 打开、未开启“只接收已信任设备”，就直接接受，然后调用 `shared.show()` 把窗口拉到前台并弹出模态框，内容可达 256 KB，并带“打开链接”按钮。这意味着办公室或宿舍网络里的任何人都能随时打断用户并投递链接。建议：未信任设备发来的文字也走确认流程（确认框已经支持显示指纹），或至少在“收到文字”对话框里显示对方地址与指纹，并把“打开链接”降为次要按钮。

3. **接收方失败原因不会告诉发送方。** 协议里有 `Receipt { ok: false, reason }`，但接收端从未发送过（`grep "ok: false"` 无结果）：磁盘满、校验失败、无法创建文件夹时接收端直接断开连接，发送方只看到“连接已断开：对方可能已取消，或网络中断”，会误以为是网络问题。建议：`receive_files` 出错时尽力发送带原因的 `Receipt`，再断开。

4. **后台接收没有任何通知。** 关闭窗口留在菜单栏 / 托盘后，已信任设备发来的文件会静默保存，用户不会知道（提示条只在窗口可见时出现；Windows 上隐藏窗口甚至不跑界面帧，提示条会积压到下次打开）。建议接入系统通知（macOS 通知中心 / Windows 通知），至少在“已收到”和“接收失败”时发一条。

5. **接收前不检查磁盘空间。** 确认框显示总大小，但接收后才在写盘时遇到“磁盘空间不足”，已收部分保留、其余失败。建议在确认前比较接收目录所在卷的可用空间与 `total`，不足时在确认框里警告。

6. **确认框最多显示 4 项，其余只显示“还有 N 项”。** 用户无法在接受前看到完整列表。建议列表可滚动（限高即可），或点击“还有 N 项”展开。

7. **设置页“IP 地址”的排序可能把 Docker / VPN 地址排在前面。** `local_addresses` 按“私网优先，再按数值”排序，`172.17.0.1`（Docker 桥）会排在 `192.168.x.x` 之前，而“复制”按钮只复制第一个。有 Docker Desktop 或 VPN 的 Mac 会把错误的地址告诉对方。建议：优先 Wi-Fi / 以太网接口（按接口名或排除 `docker`、`utun`、`vEthernet`），并在多地址时显示接口名。

8. **“重试”使用记录中的旧地址。** 对方 DHCP 地址变化后重试会失败。可先按设备 ID 在当前设备列表中查找新地址。

9. **Windows 托盘图标单击无反应，只响应双击（推断）。** Windows 用户习惯单击托盘图标打开窗口。建议 `TrayIconEvent::Click` 也调用 `show()`。

10. **首次关闭窗口时没有提示程序仍在运行。** 默认“关闭窗口后保留在菜单栏 / 托盘”，第一次关闭时窗口直接消失，用户可能以为已退出。常见做法是第一次收起时发一条系统通知（与第 4 条一并解决）。

11. **传输记录只保留本次运行。** 已在文档说明，但“打开 / 显示”入口随之丢失。可考虑把已完成记录写入设置目录（只保存路径与结果，不含内容）。

12. 小问题：
   - 网络停滞时 `Progress.rate` 不会衰减，速度和剩余时间会停在最后一个值而不是降为 0。
   - 手动输入的地址会永远每 3 秒探测一次，即使对应设备已出现在列表中或已被移除（`shared.manual` 只在“移除此地址”时清理）。
   - `add_paths` 对无法读取元数据的路径（权限不足、已删除）静默忽略，没有提示。
   - `Kind::Bye` 广播不验证来源，任何人都可以让某个设备从别人的列表中消失几秒（仅骚扰，3 秒后会恢复）。
   - 文件夹统计（`count_folder`）不排除 Windows 不支持的文件名，与实际发送数可能相差几个。

## 界面

1. **设备名换行时副标签溢出卡片。** 设备卡片高 112，名称允许两行（`wrapped(…, 2)`），两行名称加“Windows / 已信任”副标签的总高度超过卡片底部，副标签画在卡片外。演示数据里的 `DESKTOP-7F3K2L` 在 460 和 400 宽度下都能看到“Windows”落在选中高亮区域之外；有两行设备时会压进行间距。Windows 默认计算机名正是这种长度。建议卡片高度改为 124，或名称只留一行并截断（悬停已显示全名）。

2. **提示条覆盖设备网格。** 提示条锚定在页眉下方，正好压住“附近的设备”标题和第一行卡片的上半部分，5 到 10 秒内用户点不到被遮住的设备。建议改锚定到发送按钮上方，或放在页眉与内容之间并把内容下推。

3. **⌘↵ / Ctrl+↵ 发送文字没有任何提示。** 快捷键已实现但不可发现；可以在发送按钮的悬停提示或文字框右下角标注。

4. **右键菜单不可发现。** 信任 / 取消信任 / 移除地址只在右键菜单里，界面上没有任何提示；Mac 用户尤其少用右键。若第 1 条按建议只保留“取消信任”和“移除地址”，可以把它们改为悬停时出现的小按钮。

5. **UDP 端口被占用时状态标签写“可接收”却用警告色**，含义要悬停才知道。建议直接写“不可被发现”。

6. **文件大小用二进制单位但标为 KB / MB / GB。** Mac 访达使用十进制（1 GB = 10⁹），同一个文件在邻传里显示 0.93 GB、访达里显示 1 GB。Windows 资源管理器用二进制。二选一都可以，但建议与主要平台一致，或使用 GiB 标注。

7. **字体只有 Noto Sans SC。** 韩文、泰文等文件名会回退到 egui 自带字体或显示方框；日文假名 Noto Sans SC 可以覆盖。目标用户以中文为主，可接受，但可以加 Noto Sans 的 Latin/通用回退以保证至少不出方框。

8. **读屏软件仍无法读取界面。** 自绘控件都设置了 `widget_info`，基础已经打好，但 eframe 的 `accesskit` 功能仍未启用。启用后 VoiceOver / 讲述人即可使用，成本很低。

9. 小细节：
   - 设置页“保存位置”在 Windows 上不缩短路径，长路径几乎全被截断，只剩“C:\Users\…”；可以缩短为“…\Downloads\邻传接收”。
   - “收到文字”对话框的“复制”和“打开链接”都会关闭对话框，复制后想再看一眼就得去传输记录找。复制可以不关闭。
   - 传输记录页失败原因整段红色，文字较长时压迫感强；只把“接收失败”标红、原因用普通颜色会更好读。
   - “退出邻传？”对话框的“中断并退出”为实心红色，与“继续传输”的层级差异恰当；但 Esc / 点击背景关闭对话框等同“继续传输”，与请求确认框的“不可误关”行为一致，合理。

## 处理结果（2026-09-24 同日）

以下改动已实现，Linux 上 22 项自动测试通过（新增 2 项、改写 1 项），`cargo clippy --all-targets` 无警告，`rustfmt` 已格式化，Windows 目标（`x86_64-pc-windows-gnullvm`）通过 `cargo check` 类型检查；界面改动在虚拟显示器中重新截图核对。Mac / Windows 实机仍未运行，涉及系统通知和托盘的部分需要实机确认。

功能与安全：

1. 设备网格的右键菜单不再提供“信任此设备”，只保留“取消信任”和“移除此地址”；信任只能在收件确认框中完成。悬停提示注明右键可用的操作。
2. 未信任设备发来的文字走与文件相同的确认框（显示文字内容、地址、指纹，可勾选信任）；已信任设备的文字直接弹出。“收到文字”对话框里“复制”不再关闭窗口。
3. 接收方在接受之后失败时（校验失败、磁盘空间不足、无法写盘）发送 `Receipt { ok: false, reason }`，随后只读不写，直到对方关闭连接，避免带着未读数据关闭导致连接被重置。发送方新增一个只监听“对方提前回话”的线程，一旦触发立即停止发送并读取原因，记录里显示“对方无法保存：…”，而不是发完整批再报“连接已断开”。
4. 新增 `src/notify.rs`（notify-rust）：窗口收起时收到文件、发送 / 接收失败、已发送都发系统通知；第一次收起到菜单栏 / 托盘发一条说明（设置中记录只提示一次）。通知在网络线程触发，不依赖界面帧。
5. 接收前查询接收目录所在磁盘的可用空间（Unix `statvfs` / macOS `statfs` / Windows `GetDiskFreeSpaceExW`）：未信任设备的确认框在放不下时用红字提醒；已信任设备的请求直接拒绝并说明原因，发送方看到“对方的磁盘空间不足”。
6. 确认框列出全部条目，列表可滚动，高度随窗口收缩，最小窗口下按钮仍可见。
7. `local_addresses` 按“真实网卡 → 私网 → 数值”排序，Docker、VPN、虚拟机等虚拟网卡（按接口名识别）排在最后，设置页显示和复制的第一个地址即 Wi-Fi / 以太网地址。
8. “重试”先按设备 ID 在当前设备列表中查找新地址。
9. Windows 托盘：左键单击打开窗口，右键显示菜单；macOS 保持点击显示菜单。
10. 首次收起窗口的提示见第 4 条。
11. 小项：传输 2 秒没有新数据时速度与剩余时间归零而不是停在旧值；已出现在设备列表中的手动地址不再重复探测；无法读取的路径拖入时提示“无法读取「…」，已跳过”；文件夹统计与实际发送规则一致（跳过 Windows 不支持的文件名）。

界面：

1. 设备卡片高度 112 → 126，两行设备名加副标签不再溢出。
2. 提示条改到发送按钮上方，不再压住设备网格。
3. 文字编辑器底部与发送按钮悬停提示显示“⌘ Enter 发送”（Windows 为 Ctrl+Enter）。
4. 状态标签在 UDP 端口被占用时写“不可被发现”。
5. 传输记录里失败只把“接收失败 / 发送失败”标红，原因用正常颜色换行显示。
6. 启用 eframe 的 `accesskit`，VoiceOver / 讲述人可读取界面（自绘控件已有 `widget_info`）。
7. Windows 上“保存位置”缩短为“…\Downloads\邻传接收”。
8. 因界面新增“⌘”，按 `scripts/make_fonts.py` 重新生成了半粗字体子集（Regular 字体逐字节不变）。

未处理：传输记录持久化（需要新的存储格式，建议单独做）；大小单位二进制 / 十进制的取舍（产品决策）；韩文等字体回退（资产改动）；`bye` 广播来源验证（需要协议改动）。
